## 1. Design decision and acceptance boundary

Keep Python as the scientific authority. Build an explicit chain:

`composition + material state -> assessed thermodynamics -> eligible thermal-interface samples -> local solidification screens -> conserved segregated solid state -> subsolidus T(t) -> named transformation/precipitation model`.

Each arrow is conditional. Equilibrium, thermal G/R or literature segregation can be available only when their own required inputs have an admitted source and domain; availability of one is not admission of another. In particular, the existing unsourced liquidus entries do not admit physical liquidus-front G/R (see §4.1). Final phase fractions, CET and precipitation may remain unavailable. A missing arrow must not be filled by an empirical client fallback, constant cooling rate, borrowed alloy coefficient, or melt depth. No change to Build Job's decision ladder follows from this work.

Immediate deliverable is an honest, conserved, reproducible research chain for the existing methods. Quantitative final Ti64/AlSi10Mg microstructure and precipitation strength remain unavailable until the required state, coefficients and independent evidence exist. The current Python stepwise Scheil is retained and corrected, not replaced with the historical power law. Full coupled phase-field/CFD/KWN is not a mandatory prerequisite for the honesty fixes.

Acceptance distinguishes software invariants, numerical convergence, source reproduction and blind physical validation. Passing the first three never promotes a module to `Validated simulation`. Benchmarks must reserve untouched evaluation data before calibration and use compatible phase definitions, fraction bases, thermal intervals and microscopy protocols. Measured melt-pool depths remain excluded from this lane.

## 4. Thermal-interface coupling

### 4.1 Eligible samples and relations

Carry a co-located sample tuple `{position, time, G_vector, G, R_signed, cooling, interfaceDefinition, gradientMethod, fieldIdentity, materialIdentity, valid, reason}`. A quasi-steady translating field admits local `R=v·n`, with normal orientation/solidifying side recorded, and positive cooling magnitude `G*R` (S04 §3.1). Reject melting-side samples rather than taking an absolute rate and calling them solidification. Store actual coordinate frames and scan direction; scan speed alone is not R.

For a transient interface, define level set `F(x,t)=T(x,t)-T_interface(x,t)`. Differentiating `F(x_I(t),t)=0` gives `partial_t F + V_I·grad F=0`; its signed normal speed is `-partial_t F/|grad F|`. For a constant liquidus this reduces to `-partial_t T/|grad T|`. This is an explicitly derived kinematic identity extending the S04 travelling-field convention, not an empirical law. If liquidus depends on local composition, include that field's space/time derivatives or state the fixed-liquidus approximation. Fluid velocity U is neither V_I nor its replacement.

The derivative and speed above are in the same declared laboratory/material frame. In a beam frame moving at scan vector v, `partial_t F_lab=partial_t F_beam-v·grad F`; laboratory interface normal speed is `v·n-partial_t F_beam/|grad F|`. For a steady beam-frame field `partial_t F_beam=0`, the laboratory speed is v·n, not zero. Gate 3 uses a laboratory travelling field `T_lab(x,t)=T_beam(x-v*t)` and an independent analytic v·grad T oracle; the computed dictionary identity G*R is only an internal consistency check and cannot detect a mutant R=v.

### A5.1 Source-bound thermal route and input admission

The common route Q-T is the local liquidus-isotherm kinematics of [Ghosh et al.2017](https://doi.org/10.1088/1361-651X/aa7369), section3.1, PDF9/printed8, [author manuscript](https://arxiv.org/html/1705.06669#S3.SS1): normal projection of scan velocity and the full Cartesian temperature-gradient norm. This supplies a **kinematic definition**, not an alloy-calibrated thermal error model. The moving conduction framework is described by [Eagar and Tsai1983](https://eagar.mit.edu/publications/Eagar036.pdf), printed346s-348s, formulation and equations1-6. The actual regularized Rosenthal kernel is a repository variant of that framework, not the unmodified point-source solution. Preserve its regularization, property reduction and field identity in the estimate's assumptions. Eagar-Tsai and Goldak each retain their actual kernel and source provenance; one kernel's verification does not verify another's implementation.

For a fixed, admitted nominal threshold, `g=grad(T)`, `G=|g|`, `n=g/G` toward hotter liquid. In the steady beam frame with travel `v e_x`, use `R=v gx/G` on `gx>0`, `cooling=-partial_t T_lab=v gx=G R`, and `G/R=G^2/(v gx)`. Positions are metres, temperature differences kelvin, time seconds; x is scan travel, y transverse, z depth into the half-space. Temperature in Celsius and kelvin has the same gradient; thresholds must use the field's temperature scale. A scan-speed echo is not R. At a melting-side point no absolute-value trick makes R a solidification rate.

For a nonsteady beam field use the level-set derivation in section4.1: `R=v dot n-partial_t F_beam/|grad F|`, `F=T-TL`. An evolving composition-dependent TL requires its own derivatives. A5's minimum served route is **fixed-threshold, quasi-steady, stationary-solid-material kinematics**. A transient/OpenFOAM source with no compatible local time derivative/history remains refused, `missing-thermal-history` or `invalid-interface-sample` as applicable. D13's transient diagnostics are not substitute inputs.
