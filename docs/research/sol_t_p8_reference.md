# SOL-T finite P8 reference-input catalogue

`sol_t_p8_reference.json` supplies the finite before/after input values behind the RT7 dependency record at the declared reference request: 200 W, 0.8 m/s, 80 um, preheat293.15 K, nominal IR property context, Al AB. It contains all five shared conduction tuples plus endpoint anchors, 29 Ti64 and32 Al primary source arms, and13 IN718,12 316L and13 IN625 secondary source-arm declarations, **before module filtering/deduplication**. Every row stores its complete endpoint-sensitive input projection before/after and an explicit `changedInputs` list; unaffected inherited inputs are visible beside moved inputs.

Run `python -I docs/research/scripts/check_sol_t_p8_reference.py --check`. It independently reads the live source AST coefficients/nodes/property constants, analytically integrates affine segments with Decimal antiderivatives, reconstructs each existing source arm's input algebra, checks the committed catalogue and source hashes, enumerates arm IDs from the manifest AST add/front declarations and finite branches/loops, asserts set equality with the catalogue keys, and rejects altered arm values, missing/renamed declarations or a fabricated IN625 secondary fill. It imports only the adjacent source-only Decimal oracle, never a served module. The 5e-14 relative plus1e-18 absolute budget concerns arithmetic representation, not physical acceptance. The check writes nothing.

Covered leaves are Ts/Tl endpoint anchors for shared tuples, and K,cp,rho,alpha,A,Tl, liquid-property inputs where present, deltaT,Tref,mu and slope where the primary arm defines them. A primary `Tref=Tl+deltaT/2` is a derived audit echo of the flow evaluation coordinate; it is not an added runtime request field. Ts is an external ledger anchor for the Ti front-mean formula, not a fabricated inherited arm input. Unchanged process/vapour/length/accommodation fields are not repeated in the numeric projection; their source arms are still individually named because they inherit changed endpoint-sensitive values. Source files/arm definitions are pinned so a new or altered source declaration requires explicit reconciliation rather than silently escaping this finite inventory.

The two Al fixed-threshold arms `liquidus_863.15` and `liquidus_872.15` retain exactly their per-arm temperatures, K,cp,alpha,Tref and following viscosity; their `changedInputs` lists are empty. The latter now matches the nominal temperature/reduction. Its alias/deduplication/provenance handling remains the P8 owner's integration responsibility, not a reason to retarget its source threshold.

IN625 has a filled shared conduction tuple from its existing secondary thermophysical table, but `secondary_manifests` deliberately starts its IN625 properties empty. The catalogue preserves those null Tl/K/cp/rho/alpha/Tref/mu inputs for **every** secondary IN625 source arm. It does not borrow the filled context tuple to manufacture an available secondary manifest. The explicit IN625 vapour arm changes no endpoint-sensitive input and remains an individually named declaration.

Ti64 and secondary IN718 retain all endpoint-dependent numerical inputs; IN718 retains its viscosity law at the unchanged Tl-based reference coordinate, including both deltaT alternatives; 316L changes Tl/Tref while keeping its assigned0.007 Pa.s viscosity. Ti viscosity constants and empirical liquid-property reference temperatures are not silently shifted. All source/provenance identities still require the separate admission record and P8 owner update even where this numerical projection is unchanged.

This catalogue does not solve any field, cavity, Marangoni, surface balance or solidification quantity; compute output/band extremes, module deduplication or arbitrary user options; or claim source-transfer accuracy. Request-dependent numerical outcomes and the exact protected-case drift list remain the later installation owner's work. The finite reference catalogue supplements that work and does not replace it.
