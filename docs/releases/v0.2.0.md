# Metalliksa v0.2.0

Released 2026-10-22. Pre-1.0 research software: interfaces, data formats and results can change. Every result is labelled Screening only or Research; nothing in this release is experimentally validated.

## New

- **Ti-6Al-4V evaporative surface model (research, opt-in).** A transient enthalpy solver with Ti vapour energy loss on a fixed surface, for bare-plate Ti-6Al-4V, about 20 s per track on a CPU. Energy closes to about 1e-15. When the recoil and capillary criterion is crossed, melt depth is refused with its reason, and a separate P8 conditional linked melt-depth scenario is shown beside it with its own assumptions.
- **How this is calculated.** Main results open a panel with the equations actually used (transcribed from the code, rendered with KaTeX on demand), the inputs of that run and the source of each equation. 42 equations are listed with code and source locators in docs/research/EQUATIONS_SHOWN_2026-10-22.md.
- **P8 research arm.** Keyhole cavity depth and a linked melt-depth hypothesis with scenario bands, labelled research and not experimentally validated.
- **Solidification estimates.** Thermal gradient, growth rate, cooling rate and dendrite spacing on their own opt-in, labelled channel; G/R map cells carry a CET projection.
- **Machine calibration (user data).** Plan single tracks, then fit a per-machine depth correction from your own cross-sections. Currently served for 316L Rosenthal depth only, behind a gate, and labelled until the measurement method is recorded.
- **Static demo** at https://canerganis.github.io/metalliksa/ (recorded snapshots, no solver).

## Easier to use

- Plain-English labels and module names (maintainer-approved wording table), a sidebar grouped by task, one-line purpose per module, evidence details one click away.
- A melt pool summary card with units and evidence labels, consistent number and unit formatting, labelled chart axes.
- The guided tour reaches a result: Screening width and depth beside the NIST AMB2022-03 measurement, labelled a comparison and not a validation.
- New sessions start in Quick Screening, which always returns a labelled result.
- The process window explains why no cell is printable when that happens.
- GPU (CUDA) controls appear when a device is reported; CALPHAD recalculates when a slider is released and shows the expected time.

## Fixed

- CALPHAD phase-fraction chart drew false gaps and spikes (absent phases were left undefined in a stacked chart).
- G/R map now says why it has no value instead of rendering empty cells.
- Clearer messages for a stale engine status and for evaporative runs that leave the model's declared temperature range.
- Linux CI is green: fixture freshness checks are platform tolerant (structure exact, floats within 1e-9), plus test fixes for worker startup and supplied-material snapshots.

## Known limits

- The screening depth underestimates keyhole-mode tracks (about half on the NIST AMB2022-03 case 0). The model error scorecard passes 0 of 30 cells, so no calibrated mode is offered. Blind testing needs open single-track cross-section data with a stated surface datum, beam definition and measured power.
- Standard (transient conduction) mode stops at the boiling limit for typical inputs; use Quick Screening, or the Ti-6Al-4V evaporative model for Ti-6Al-4V on a bare plate.
- Keyhole ray tracing and GPU solvers need NVIDIA Warp in the Python runtime (`pip install warp-lang==1.17.0`).

Built with NVIDIA Warp for the GPU solvers and with AI coding agents (Anthropic Claude, OpenAI Codex) as part of the team. Data: NIST AMB2022-03, CMU and KU Leuven single-track datasets, MatCalc open databases.
